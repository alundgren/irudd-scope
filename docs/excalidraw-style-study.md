# Excalidraw visual direction for Scope

This is a proposal for the mockups in the [prototype brief](visual-prototype-brief.md). The [interactive specimen](mockups/appearance-study.html) compares a compact tab strip with a floating strip, switches appearance, searches artifacts and settings, and demonstrates a slide-in diagram chat. All content is synthetic. The diagram is an illustration, not an embedded editor. Chat previews a fixed sample edit without calling a model. Final app styling is still undecided in [ux.md](../ux.md).

We can get close to Excalidraw's interface with cool neutral backgrounds, violet selection, small rounded controls, restrained shadows, and very little persistent navigation. Its exact fonts are not needed for that result. I recommend the compact strip. It keeps the content unobstructed and the open artifacts visible.

Use the published MIT editor and preserve its license and bundled third-party notices. Choose resources for Scope's own interface separately. This proposal does not require an editor fork or replacement of its default fonts and icons.

The source references below use Excalidraw commit `afed9e6e27dd1cd5cc52857a405f7bea5312d813`. The live site and source agree on Assistant for interface text and `#6965db` for the light accent.

The code and included resources can have different licenses. OFL fonts permit commercial bundling under their terms; they are not proprietary paid fonts. The distinction matters when copying a font separately into Scope. It does not turn the MIT editor into a proprietary component or introduce a requirement that every dependency use MIT.

The proposed interface rules are deliberately stricter than the general house UX rules:

1. Reserve one 44px strip for tabs and workspace navigation. Do not add a separate app heading, breadcrumb row, permanent status bar, or secondary toolbar across all artifact types.
2. Give tabs all remaining width after the workspace menu, search, and focus buttons. An artifact's title is its tab label. Do not repeat it above the content unless it is part of the document itself.
3. Keep the active tab visible. Scroll a single row when twelve tabs do not fit, retain readable titles, and expose every full title through search. Never wrap tabs into extra rows or shrink them into unreadable labels.
4. Keep session inspection, session analysis, settings, provenance, and connection details out of the default tab strip. Open tools on request through search. Show a persistent connection message only while it changes what the user can do.
5. Give new arrivals and background updates a small indicator without changing selection. A conflict affecting an edited diagram deserves a clear choice before replacement; it must not be reduced to an unexplained dot.
6. Put secondary actions in the workspace menu or the active artifact's contextual controls. Tooltips and keyboard focus must expose every icon's name. Do not add instructions to explain an unclear permanent control.
7. Show selection with a tinted background and a short solid marker, so hue is not the only signal. Use violet for selection, keyboard focus, and the occasional primary action. Keep success colors out of ordinary content.
8. Use shadows only for menus, dialogs, and the floating comparison. Ordinary artifact content has no surrounding card, border, or shadow. Keep a document's comfortable reading width without restricting diagrams or images to that width.
9. Focus mode retains the current artifact component, scroll, and diagram zoom. Hide workspace navigation and use the editor's zen mode where appropriate. Put the small exit in the top-center area vacated by the editor toolbar, after verifying its menu, library, and zoom controls remain clear. Escape closes an active dialog or editor interaction first, then exits focus mode.
10. A diagram's Ask agent control opens a conversation from the right. Keep it closed by default and scoped to the artifact. At desktop widths, reserve up to 360px while keeping the canvas visible. Below 700px, overlay it instead. Closing, tab changes, and focus mode preserve the conversation and draft. Focus mode temporarily hides the panel and restores it on exit. Respect reduced-motion preferences. The provider runs through the Mac app; Gemini 3.8 Flash via OpenRouter is the initial selection.
11. Make Search and Settings direct workspace menu actions. Settings opens with its search field focused above the controls. Match names and related terms, offer a clear action, and explain empty results. Global search should find specific settings and open the matching controls. Local publishing needs no connection form. Configure optional remote forwarding outside the desktop UI.

The palette starts from Excalidraw's [theme variables](https://github.com/excalidraw/excalidraw/blob/afed9e6e27dd1cd5cc52857a405f7bea5312d813/packages/excalidraw/css/theme.scss). Scope adds a quiet strip color, secondary text, and a decorative divider. These are concrete values for the study, not approved production tokens.

| Token        | Light     | Dark      | Use                                             |
| ------------ | --------- | --------- | ----------------------------------------------- |
| `--canvas`   | `#ffffff` | `#121212` | Artifact background                             |
| `--panel`    | `#ffffff` | `#232329` | Menus and dialogs                               |
| `--strip`    | `#f6f6f9` | `#1b1b1f` | Compact tabs                                    |
| `--text`     | `#1b1b1f` | `#e3e3e8` | Primary text and selected labels                |
| `--muted`    | `#626271` | `#aaaab5` | Secondary text on canvas, panel, or strip       |
| `--line`     | `#e6e6ed` | `#3d3d49` | Decorative dividers                             |
| `--outline`  | `#767680` | `#8e8d9c` | Boundaries where recognition depends on them    |
| `--accent`   | `#6965db` | `#a8a5ff` | Focus rings, selection markers, primary actions |
| `--selected` | `#e3e2fe` | `#403e6a` | Selected controls, with primary text            |

Primary text has at least 12.2:1 contrast on the ordinary backgrounds above. Secondary text has at least 5.5:1. Use primary text on selected backgrounds, where dark secondary text would fall below 4.5:1. Violet is not a general text color on tinted backgrounds. A 2px focus ring uses the accent with a 2px offset.

Use `system-ui, -apple-system, BlinkMacSystemFont, "Segoe UI", sans-serif` for the interface. Use 14px/20px for tabs and menus, 12px/18px for secondary details, and 16px/26px for reading. Weights are 400, 500, and 600. The study demonstrates Comic Shanns for diagram text. The embedded editor can retain its existing font choices. Ordinary interface text stays plain.

Spacing uses 4, 8, 12, 16, 24, and 32px. Compact controls have a 32px target inside the 44px strip. Corners are 6px on small controls, 8px on selected tabs and menus, and 12px on dialogs. The selected tab remains distinct without a pill around every other tab.

Appearance has exactly three values, System, Light, and Dark. The initial value is System. Keep this preference local to the Mac, alongside desktop preferences. It belongs in settings, not beside the main tabs.

In the browser specimen, resolve System with `matchMedia("(prefers-color-scheme: dark)")` and listen for changes. Store the preference `system`, not the current resolved value. Apply it before the first paint, and retain manual overrides until System is chosen again.

In Electron, use [`nativeTheme.themeSource`](https://www.electronjs.org/docs/latest/api/native-theme) with the same three values. Its default is `system`; `shouldUseDarkColors` and the `updated` event provide the effective appearance. Electron main can apply the saved preference before opening the window, including the initial background, and keep native menus and renderer appearance consistent. Do not add raw Electron access to the sandboxed renderer.

Pass the resolved `light` or `dark` value to Excalidraw's documented [`theme` prop](https://docs.excalidraw.com/docs/@excalidraw/excalidraw/api/props#theme). Suppress its duplicate theme switch through [`UIOptions.canvasActions.toggleTheme`](https://docs.excalidraw.com/docs/@excalidraw/excalidraw/api/props/ui-options). Apply shared tokens to both `.excalidraw` and `.excalidraw.theme--dark` using the [documented CSS customization](https://docs.excalidraw.com/docs/@excalidraw/excalidraw/customizing-styles). Keep typography changes limited to Scope's interface unless there is a visible inconsistency worth correcting inside the editor.

The renderer and native window should change together without remounting the active artifact. Appearance must not rewrite diagram colors or revisions. Keep image pixels intact. An isolated HTML preview keeps its own authored colors unless that artifact provides its own appearance rules; never use a blanket inversion filter to force it dark.

The house task focus, reversible actions, plain wording, keyboard behavior, and restrained typography still apply. The deliberate departures are cool neutrals instead of earth tones, system typography instead of bundled IBM Plex, stronger text contrast, and both light and dark appearance because the Mac and embedded editor support them.

The specimen is opened directly from `mockups/appearance-study.html`. Its workspace menu has Search and Settings. Appearance and navigation comparisons live in searchable Settings. Search is Command-K on Mac or Control-K elsewhere; Command/Control-comma opens Settings. Arrow keys, Home, and End switch tabs while the tab row has focus. Command/Control-Shift-T reopens the last closed tab. Command/Control-Shift-F toggles focus. Escape closes a dialog first, exits focus when active, or closes diagram chat in the ordinary view. In the native app, Command-W should close an artifact view; the browser specimen leaves that browser shortcut alone.

In chat, Enter sends and Shift-Enter adds a newline. A pending mock reply exposes Cancel and leaves the canvas intact when canceled. Use the suggested sample request to emphasize the local API in the illustration. The same fixed demonstration follows any submitted text; it is not a working model. Fake key entry demonstrates saved, replace, and remove states without persisting or sending the value. Production conversation and searchable Settings still need integration with Electron's existing provider and credentials code.

The remaining full prototypes should cover the [brief's](visual-prototype-brief.md) credential failures, artifact arrival, updates and edit conflicts, empty workspace, local storage errors, downloads, and isolated HTML. Those flows are outside this appearance study. Mac system appearance, native window controls, editor controls in focus mode, and export behavior need checks against the actual Electron and Excalidraw integration.
